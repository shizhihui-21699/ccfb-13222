# 公开可验证年会抽奖

回应"抽奖内定"质疑:结果不由服务器说了算,任何人拿公开数据都能在浏览器里独立复算。

## 运行

```bash
cargo run          # 默认端口 9317,可用 PORT=xxxx 覆盖
# 打开 http://127.0.0.1:9317
```

## 协议(承诺 → 开奖 → 验证)

1. **创建(开奖前)**:服务器公布
   - 完整参与名单(规范化:每行 `id:name`,`\n` 连接,UTF-8)
   - `list_hash = SHA-256(规范化名单)` —— 名单的摘要承诺
   - `commitment = SHA-256(server_seed)` —— 服务器 32 字节秘密种子的承诺
2. **开奖**:取一个**承诺之后才产生**的公开随机源 `public_random`(本地模拟:60 秒一轮,
   轮次开始后才生成该轮的值),计算
   - `seed = SHA-256("lottery-v1" ‖ server_seed ‖ public_random ‖ list_hash)`(均为原始字节)
   - 确定性随机数 `rand_u64(i) = SHA-256(seed ‖ i 的 8 字节大端)` 前 8 字节(大端)
   - 按奖项顺序抽取:`j = rand_u64(counter) % 剩余人数`,取出 `pool[j]`,counter 递增
   - 开奖后公开 `server_seed` 和 `public_random`
3. **验证(任何人在浏览器内完成,无需信任服务器)**:
   - 重算名单 SHA-256 = 公布的 `list_hash` → **名单开奖后被改会被发现**
   - 重算 SHA-256(server_seed) = 公布的 `commitment` → **服务器无法中途换种子**
   - 公开随机源生成时间晚于承诺时间 → **服务器承诺时无法预知结果**
   - 用公开算法重算中奖名单 = 公布结果 → **结果不是编的**

## 目录

- `src/main.rs` — Axum 后端:场次管理、承诺、开奖、协议实现(含单元测试)
- `static/` — Preact 前端(htm,已本地 vendor,无外部 CDN 依赖):创建、开奖、独立复算
- `scripts/verify.mjs` — 命令行复算脚本:`node scripts/verify.mjs session.json`

## 说明与边界

- 公开随机源是**本地模拟**的。生产环境应换成真正不受主办方控制、且承诺时不可预知的源:
  drand 联盟链随机信标、NIST Randomness Beacon、未来某个比特币区块哈希等
  (创建时公布"将使用第 N 轮/块高 H 的值",开奖后任何人可独立获取该值)。
- 数据保存在内存中,重启即清空(演示用途)。
- 防的是"结果被操纵":主办方要么接受承诺锁定的名单和种子,要么放弃开奖;
  它不能证明名单本身该包含谁(那是人事问题,不在密码学范围内)。
